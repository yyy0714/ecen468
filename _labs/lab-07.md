## Objectives

In this lab, we will implement a 256K x 8-bit SRAM design using Verilog. We will use Synopsys VCS to simulate the designed model for verification. We will also use Synopsys Design Vision to synthesize the design.

## A Brief Introduction to SRAM

We will implement a Static Random Access Memory (SRAM) with a storage cell structure that does not require a refresh. Therefore, it operates faster than Dynamic Random Access Memory and is used as fast-cache memory in a computer.

We will start by implementing a simple SRAM cell. Then we will perform (1) functional simulation, (2) synthesis, and (3) gate-level simulation with the netlist on that cell. After that, we will implement a 256K SRAM and perform only a functional simulation. The 256K SRAM will be used in future labs.

The block diagram of a basic SRAM cell is shown in the figure below. It has active-low inputs for both cell select (`CS_b`) and write enable (`WE_b`). The cell-select signal is generated by a decoder that selects among multiple cells in the same system. Note the absence of a clock signal. Storage registers and register files are implemented with flip-flops, while the storage devices of SRAM and DRAM use transparent latches. This implementation supports asynchronous operation and minimizes the time a RAM ties up a shared bus.

1. SRAM is sensitive to `CS` and `WE`.
2. Output high impedance when `CS` is high.
3. `WE` = 1: Read from SRAM; `WE` = 0: Write to SRAM.

If there are compile errors, recheck your design and fix your code. Once compilation succeeds, go to the next step to view the results.

Once verification is complete, we will use Design Vision to synthesize the design. For convenience, invoke Design Vision from a separate directory to isolate the intermediate files it generates.

```bash
## Create and navigate to a separate working directory.
mkdir $HOME/ECEN468/Lab7/src1/dv_Work
cd $HOME/ECEN468/Lab7/src1/dv_Work

## Launch Design Vision
source /opt/coe/synopsys/syn/V-2023.12-SP1/setup.syn.sh
design_vision &
```

In Design Vision, we first link the libraries.

- Add `osu018_stdcells.db` to **Link Library** (Remove all other library files)
- Add `osu018_stdcells.db` to **Target Library** (Remove all other library files)
- Add `osu018_stdcells.db` to **Symbol Library** (Remove all other library files)
- Click on **OK**

![Design Vision library setup]({{ "/assets/files/lab07/img/2.png" | relative_url }})

Next, we *Analyze* the design. During analysis, the tool reads VHDL or Verilog files, checks for proper syntax and synthesizable logic, and stores the design in an intermediate format.

- Click on **File -> Analyze**.
- In the pop-up window, add `SRAMCELL.v`, and click on **OK** as shown in the figure below.

![Analyze dialog in Design Vision]({{ "/assets/files/lab07/img/3.png" | relative_url }})

Next, we *Elaborate* the design. Elaboration creates a design from the intermediate format produced by analysis, replacing the HDL operators with synthetic operators and determining the correct bus sizes.

- In the interactive text area located at the bottom of the graphical user interface, type `elaborate SRAMCELL`

![Elaborated SRAMCELL design in Design Vision]({{ "/assets/files/lab07/img/4.png" | relative_url }})

Print Schematic:

- Right-click on `SRAMCELL` -> **Schematic View**, as shown in the figure below.
- You can double-click on the `SRAMCELL` block in the schematic to check the detail of the netlist.
- Click on **File -> Print** to save the schematic as a PDF file.

![Schematic view of the SRAMCELL netlist]({{ "/assets/files/lab07/img/5.png" | relative_url }})

Synthesize the module:

- Click on **Design -> Compile Design**.
- In the pop-up window, click on **OK** as shown in the figure below.

![Compile Design dialog in Design Vision]({{ "/assets/files/lab07/img/6.png" | relative_url }})

After synthesis, we save the optimized netlist as a Verilog file:

- **File -> Save as**
- Please enter `SRAMCELL_gate.v` as the file name and choose **Verilog** as the file type.
- Check the option **Save All Designs in Hierarchy**.

Save the Standard Delay Format (SDF) by running the following command in the command window:

`write_sdf SRAMCELL.sdf`

You may now close Design Vision.

With the SRAM cell saved as Verilog and SDF, we will do a Gate Simulation on it. First, copy these two files out of the current directory:

```bash
cp ./SRAMCELL_gate.v $HOME/ECEN468/Lab7/src1/
cp ./SRAMCELL.sdf $HOME/ECEN468/Lab7/src1/
cd $HOME/ECEN468/Lab7/src1/
```

We will use the previous test bench as a template to create a test bench for the gate simulation.

`cp SRAMCELL_tb.v SRAMCELL_gate_tb.v`

Open the new test bench `SRAMCELL_gate_tb.v` and make the following modifications:

- Make sure the following three lines are on the top of the file.

  ```verilog
  `timescale 1ns/10ps
  `include "SRAMCELL_gate.v"
  `include "osu018_stdcells.v"
  ```

- Remove the following line if it exists.

  ```verilog
  `include "SRAMCELL.v"
  ```

- Make sure the following two lines are at the bottom of the file (within the module).

  ```verilog
  initial
      $sdf_annotate("SRAMCELL.sdf", SRAMCELL_01);
  ```

- Change the name of the dump file in the following line in the test bench.

  `$dumpfile("wave_gate.dump");`

Make sure all the files listed below are available in your current directory.

- `SRAMCELL_gate.v`
- `SRAMCELL.sdf`
- `osu018_stdcells.v`
- `SRAMCELL_gate_tb.v`

Once we have the files ready, we can run the following command to start the simulation.

```bash
source /opt/coe/synopsys/vcs/W-2024.09-SP2-4/setup.vcs.sh
vcs -full64 SRAMCELL_gate_tb.v
```

If no error occurs, do the next step.

`./simv`

Take a screenshot of the simulation output and include it in your report.
